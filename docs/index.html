CUT
The LLM classification path, on measured evidence

Built a Claude-based classifier for ambiguous decline codes, then measured its actual ceiling before trusting it: majority-class floor 43.1%, heuristic 46.6%, Bayes-optimal ceiling 48.7%. Roughly two points of headroom, on 6% of events. Cut the LLM call rather than ship something that sounds impressive and does nothing.

FOUND
The RBI notice clock restarted at execution time

A deferred mandate debit re-checked its 24-hour compliance window using the moment it fired, not the moment the notice was sent — so the window never elapsed. 81/81 deferred actions were being permanently rejected. Fixed by carrying the original notice timestamp forward; verified 0/81 rejected afterward.

FOUND
Replaying the same batch twice produced two different ledgers

Re-validation entries were keyed with uuid4() — random by definition. That silently broke the "replayable audit trail" claim on every single run. Replaced with a deterministic id derived from the decision and timestamp; two replays of the same batch now produce byte-identical chains.

FOUND
The tamper demo said "chain OK" after tampering

The demo picked the first gate result to flip — which happened to already be PASS, so flipping it to "pass" changed nothing. A tamper demo that shows the chain surviving tampering disproves the exact thing it exists to prove. Fixed to target an actual BLOCK verdict and name the exact entry that breaks.

FOUND
receipt is not an idempotency key

Assumed Razorpay deduplicated on the receipt field. Tested it against the live sandbox: sent the same receipt twice, got back two different order IDs. In production that's a double charge on a network retry. Idempotency is now enforced client-side, with the durability limitation stated rather than hidden.

FOUND
A headline safety test was passing vacuously — twice

The test proving retries never exceed the cap read the cap from the same config it was validating (loosen the config, the assertion loosens with it), and generated payment IDs so unique that no payment ever reached a second retry — nothing was ever being capped. A mutation-testing pass caught both. Fixed with a hardcoded ceiling and a focused strategy that forces accumulation.

FOUND
A 15,000-event batch took two minutes instead of sixteen seconds

Discovered while building the scale-stress test — a batch-wide lookup was being rebuilt from scratch inside a loop over every deferred action: true O(events × pending), invisible at 1,000 events. Hoisted out of the loop; confirmed linear scaling from 1,000 to 15,000 events afterward.
